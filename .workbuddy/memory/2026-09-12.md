## 续四：重跑 v9 暴露的真问题 —— Q13 不是截断，是 JSON 非法转义

### 我上一轮的判断是错的
之前把 Q13（电烤箱铭牌表格）失败记成「JSON 在 options 数组中途被截断」，
并据此加了「解析失败重试」。重跑两次仍失败，于是写了探针：

```
finish_reason = stop（不是 length）
内容 732 字完整，尾部是正常的 }
JSONDecodeError: Invalid \escape @ 字符 80
位置附近: | **\*\*牌电烤箱** | |
```

**模型把 markdown 的加粗星号写成了 `\*`**，JSON 只允许 `" \ / b f n r t u`
这几种转义，整条回复被拒收。四次请求（不传/4096/8192/16384）全截在同一字符
→ 不是抖动，重试永远救不回来。

### 修法
`vlm_client.parse_json` 前置 `repair_invalid_escapes()`：
正则 `\\(?!["\\/bfnrtu])` 去掉非法转义的反斜杠、保留字面字符。
**不能反向补反斜杠**（`\*` → `\\*`）—— 会在正文里凭空多出字符。
合法转义（`\\` / `\n` / `\"` / `\u`）原样保留，有单测守着。

实测：探针由「解析失败」变 `OK options=4`。
顺带显式传 `max_tokens=8192`（不再依赖端点默认值）。

**教训**：截断与非法转义在 `finish_reason` 上都是 `stop`，
不看 `JSONDecodeError.msg/pos` + 附近原文就分不清。

## 续五：我的转义修复把 v9 跑挂了 —— 正则没按「两字符一对」消费合法转义

### 现象
转义修复后再跑 v9 → **闸门阻断**：`orphan_pages=[29,30,36,38]`、`blocked=true`，
同时 Q26 答案从「2 条来源 + 2 张答案图」退化成「1 条 + 0 张，LaTeX 丢失」。
`excluded_lines` 662 → 578（少 84 行 = 那 4 页的全部行）。
表象**完全像网关抖动**（上一轮 PASS 这轮 FAIL），差点就归因成抖动。

### 定位（关键：别只看告警，告警文案本身在骗人）
`extract.json` 的 warning 里有 4 条
**「第 N 页整页转写失败，该页内容缺失：视觉模型回复不是合法 JSON: ```json …」**。
`build_line_inventory` 对单页转写失败是跳过该页，而 `audit._no_text_pages` 会把
「没有文字行但有图」的页算成孤儿页 → 阻断整份文档。
**所以任何一页转写失败都表现为「孤儿页」，看到孤儿页先去 grep 这条 warning。**

写探针 `_probe_page_transcribe.py`（4 次请求，1 分钟）打证据：

```
finish_reason=stop   completion_tokens≈1050   content 1800~2200 字  围栏闭合
剥围栏后 json.loads: OK      ← 模型侧完全没问题
过 repair_invalid_escapes 后 json.loads: FAIL  Invalid \escape
  29 页 @1829  \\%      →  \%      改动 2 字符
  30 页 @72    \\approx →  \a      改动 1 字符
  38 页 @984   \\Delta  →  \D      改动 7 字符
  36 页 无 \\X-with-illegal-X，改动 0 → 唯一通过的一页
```

### 真根因
上一版 `repair_invalid_escapes` 用 `re.sub(r'\\(?!["\\/bfnrtu])', "", text)` **逐字符**
判断，`\\approx` 里**第二个**反斜杠后面跟的是 `a`（不在合法表里）→ 被删 → 合法 JSON
变成非法。`\\frac`/`\\rho`/`\\times` 因为 `f`/`r`/`t` 恰好合法而侥幸没坏，所以只暴露了 3 页。

再加上 `parse_json` 的报错是 `f"...: {text[:300]}"` —— 出错点在 1829 字，
**报错里根本看不到**，这才让排查绕了一大圈。

### 修法
① `repair_invalid_escapes` 改按索引扫描，合法转义（`" \ / b f n r t` 与 `\uXXXX`）
