# 阶段 4：图片排版与编辑任务计划

> 状态：待产品细节确认  
> 目标：让教师在题目文档中直观编辑图片，支持横向并排和纵向堆叠两种排版方式，编辑区与预览/PDF/Word 保持一致。

## 1. 产品范围

图片作为题目文档中的块级节点，与段落和选项连续编排。多张连续图片默认横向并排（与预览/PDF 一致），教师可切换为纵向堆叠。第一版不做浮动环绕、文字环绕和自由定位。

### 核心问题

当前编辑器将每张 `image` 节点渲染为独立块级 NodeView，导致连续图片纵向堆叠、大小不一致；而预览/PDF 后端将连续图片收集为 flex 行并排渲染。编辑区所见非所得。

## 2. 数据模型变更

### 2.1 图片节点新增 `layout` 属性

```jsonc
// BlockImage 节点 attrs
{
  "src": "asset://practice/xxx.png",
  "align": "center",        // left | center | right
  "width": null,            // null/'fit' | 数字(百分比) | '50%'
  "layout": "row"           // "row" = 与相邻图片并排 | "block" = 独占一行纵向
}
```

- `layout` 默认值 `"row"`：连续多张图片自动并排。
- 教师可手动将某张图设为 `"block"`，使其独占一行（纵向排列）。
- 单张图片默认仍为 `"row"`，但因为没有相邻图片，实际显示为居中单图（与当前行为一致）。

### 2.2 向后兼容

- 旧数据无 `layout` 字段，迁移时默认填充 `"row"`（与后端当前并排渲染行为一致）。
- 后端 `doc_render.py`、`render_service.py`、`docx_export.py` 已按连续图片并排处理，无需改动数据层。

## 4. 本阶段不做

- 不做图片浮于文字上方或下方（文字环绕）。
- 不做四周型、紧密型文字环绕。
- 不做自由旋转。
- 不做复杂裁切、标注和滤镜。
- 不做页面绝对坐标拖动定位。
- 不做图片裁切。
- 不做图片组容器节点（用 `layout` 属性控制，不引入新的 group 节点类型）。

## 5. 验收标准

1. 编辑器中连续多张图片默认横向并排显示，大小均匀，与预览/PDF 一致。
2. 教师可将图片切换为纵向独占排列（`layout: "block"`）。
3. 可在并排和纵向之间自由切换，编辑器即时反映。
4. 拖拽缩放、替换、删除、reorder 操作正常。
5. PDF 和 Word 中图片排版与编辑器所见一致。
6. 大图和损坏图片不会让编辑器崩溃。
7. 旧数据（19 道多图题目）迁移后显示正确。

## 6. 实现要点

### 编辑器 CSS 并排方案

```css
/* 连续 layout="row" 的图片自动并排 */
.qre-img[data-layout="row"] + .qre-img[data-layout="row"] {
  display: inline-flex;
  vertical-align: top;
}
/* 或用 flex 容器包裹连续 row 图片（由 NodeView 层检测） */
```

具体实现需在 NodeView 层或 CSS 层选择一种：
- **CSS 方案**：简单，但工具条定位在 inline 模式下需额外处理。
- **NodeView 分组方案**：检测连续 row 图片，包裹在共享 flex 容器中；工具条在各自子节点内。更可控，推荐。

### 后端 layout 属性消费

`doc_render.py` 的 `flush_imgs()` 收集逻辑需检查每张图的 `layout`：
- `layout="row"` → 加入并排收集。
- `layout="block"` → 立即 flush 已收集图片，然后单独渲染该图。
