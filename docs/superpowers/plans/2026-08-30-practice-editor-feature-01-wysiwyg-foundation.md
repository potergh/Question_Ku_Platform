# 阶段 1：单题所见即所得编辑器基础任务计划

> 状态：已完成（2026-08-30 验收通过）  
> 目标：将分散的题干、选项输入框替换为一道题一个“小型 Word”的连续编辑体验。

## 1. 用户场景

教师在左侧选中一道题，中间打开该题的完整内容。题干、图片占位、选项在同一个编辑区域连续显示。教师直接选择文字并排版，停止输入后自动保存，也可以点击保存按钮立即保存。

## 4. 验收标准

1. 选择一道题后，中间只出现一个连续编辑画布。
2. 题干和选项不再表现为多个分散输入框。
3. 基础格式可直接操作并立即看到效果。
4. 自动保存和保存按钮均有效。
5. 切换题目后修改不丢失。
6. 粘贴 Word 内容不会带入混乱字体和间距。
7. 右侧真实预览在停止编辑后刷新。

## 6. 完成记录（2026-08-30）

### 实现要点

- 技术栈：Tiptap 2（@tiptap/core 2.27.2 + @tiptap/vue-3 2.14.1），组件 `frontend/src/components/richeditor/QuestionRichEditor.vue`，通过 `:key=selected.id` 保证切题销毁重建。
- 架构：反向双写——编辑器以 `rich_document` 为唯一真源，后端 `apply_doc_to_question` 反推旧块/快照保证导出兼容；保存端点 `PUT /api/practices/{id}/questions/{qid}/document`，保存前 `validate_doc` 校验 schema v1。
- 选项：optionGroup/option 自定义节点，Enter 在选项内换段（hardBreak）、Ctrl+Enter 新建下一选项，增删（确认）/移动/自动重编号 A–N。
- 自动保存：停输入 1 秒防抖，四态状态、失败重试、切题前强制落盘（flush）、离开保护、saveSeq 序号防旧请求覆盖；中文输入法 composing 守卫。
- 安全粘贴：transformPastedHTML 剥离外部图片/脚本/事件属性/危险 URL/内联样式。
- 恢复：整题确认后重建文档并保存刷新；答案与解析不显示、不迁移。
- 预览：保存成功后延迟刷新，不重复生成，提供手动刷新。
- tiptap 2.27 陷阱：`content` 必须传完整 `{type:'doc', content:[...]}` 对象，裸数组会被当作 Fragment 导致崩溃；带 NodeView 的节点仍需 `renderHTML`。
